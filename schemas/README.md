# `scenario` JSON schemas

This directory hosts the JSON schemas of input / output files for the `scenario` library.


## Design details

For its ability to save explanatory comments,
the YAML format is used to define the source schemas.

The [update-schemas.py](../tools/update-schemas.py) then generates the *.json* equivalent files
that one can use without requiring the YAML technology.

The *.json* versions constitute the official JSON schemas for tool compatibility,
but the *.yml* versions are easier to read for the understanding.

The reference JSON schemas are hosted under https://github.com/alxroyer/scenario/blob/master/
so that they remain easily available, including with helper tools like IDEs.

The version information is not held by the tag (not "/blob/vX.Y.Z/" in the URL)
but by the file name ("xxxx-vX.Y.Z.schema.json")
in order to be able to fix or refine these schemas after the release has been published.


## Scenario reports

### [v0.1.0](scenario-report_v0.1.0.schema.yml)

First version with [v0.1.0](scenario-report_v0.1.0.schema.yml).

No changes in scenario reports in v0.2.0 nor v0.2.1.
[v0.1.0](scenario-report_v0.1.0.schema.yml) remains applicable for these versions.


### [v0.2.2](scenario-report_v0.2.2.schema.yml)

Changes from previous version [v0.1.0](scenario-report_v0.1.0.schema.yml):
- `#/$defs/known-issue`:
    - `id` property made optional, and not generated by default.
    - Optional `level` and `url` properties added.

Backward compatibility:
- Previous versions of scenario reports can still be imported by `scenario` v0.2.2.
- Previous versions of scenario reports can still be verified against this new JSON Schema [v0.2.2](scenario-report_v0.2.2.schema.yml).
- **New scenario reports may no longer be imported by earlier versions of `scenario` (due to `id` fields missing).**
- **New scenario reports v0.2.2 may no longer be verified against previous versions of JSON schemas (due to `id` fields missing).**
